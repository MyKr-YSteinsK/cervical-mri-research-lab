# 01｜项目 Brief：宫颈癌 MRI 研究实验室

## 1. 身份与定位

- Project ID（建议）：`Cervical-MRI-Research-Lab`，最终名称可由用户决定。
- 当前起点：已完成六篇指定宫颈癌 MRI 影像组学疗效预测论文的第一轮技术导读；对 Python/实际医学图像处理与深度学习实操**尚无经本项目验证的经验**。现准备从零开展**真实、可重复**的研究工程。
- **用户已明确**：偏好宫颈癌本病种；尽量与六篇论文的研究对象、影像类型和表征方法保持关联。当前可接受先开展分割、影像预处理等前期任务，暂不强求疗效二分类。倾向复杂综合研究，愿意学习并亲自编写关键代码；不用/极少用 Codex。可独立开新的 GPT Project。
- **CMRL-00 专项授权（仅限本任务）**：用户按当前 Plan 授权 Codex 自动完成仓库初始化、数据源可用性与公共元数据核验、非敏感文件清点及证据报告。MRI 数据处理、分割、Radiomics、训练和解释性核心代码仍由用户逐步学习、编写和运行。未来扩大范围须另行授权。
- **用户未最终批准**：指定某个数据集为唯一标准数据；固定任何模型架构；一定要做 Habitat/Transformer/联邦学习；任何特定发表目标；必须复现六篇原始临床性能；跨癌种作为主任务。

## 2. 科学目标、工程目标、教学目标

科学：围绕宫颈癌 MRI 建立**由真实可得的数据支持**的研究问题，以可复核的实验检验肿瘤分割、影像表征、特征稳定性、跨中心泛化、或在真实标签允许时的疗效/预后预测假设。创新仅作为实验候选，不能先宣称突破。

工程：亲自完成数据合法获取/匿名化检查、目录与数据索引、医学影像空间核查、预处理、baseline、训练与推理、评价、实验对照、结果追踪和复现性报告。

教学：每个新概念均能解释其目的、约束、公式、数据形态、代码所在模块、输入输出、常见失败和验证方法；用户独立写改核心代码，GPT 负责讲解、审阅、定位问题，不代替其完成全工程。

## 3. 当前范围

**CORE（已确认）**：R0 数据审计与选题、合法数据获取、配套 Python/虚拟环境教学、DICOM/NIfTI/NRRD 与空间方向、ROI/VOI、数据质控、与实际数据相匹配的 baseline、正确患者级评价、实验记录；围绕宫颈癌 MRI 保持与原六篇的技术关联。

**CONDITIONAL（达条件才加入）**：自动分割（数据有 ROI）；稳定 Radiomics（有可靠 ROI/扰动协议）；Habitat（有足以形成亚区域的空间影像与合理任务）；多序列/纵向融合（有对应影像）；真实患者应答二分类（有病种、治疗方式、时间点、终点一致且许可使用的标签）；DFS/OS（事件与删失记录齐全）；跨中心评价（中心身份及独立患者可核验）。

**OPTIONAL（尚未批准）**：ViT/Transformer、MedSAM/nnU-Net 扩展、联邦学习、公平性、外部中心协调、自监督/半监督学习、论文投稿、跨癌种迁移。

**NON-GOALS**：虚构患者、编造 pCR/DFS 标签、把图像增强当新患者、利用真实测试数据挑参、把内部切片分割成绩冒充患者级外部验证、以模型复杂性或高 AUC 冒充临床有效性；真实个人诊疗建议；日常 Codex 主导开发；自动访问/公开任何医疗隐私信息。

## 4. 数据/证据权威层级

1. 数据所有者的许可证、授权书和实际下载文件。
2. 原始论文 Methods/Results/附录、官方数据发布页与文件说明（可相互核查）。
3. 用户本地运行日志、环境与真实结果。
4. GPT 的理论解释、通用示例、未执行代码（必须标记）。

不得把论文作者的表现写成自己已复现。不得把官方元数据确认直接升级为“已下载并检查全部数据”。

## 5. 可接受的成果

- R0：有证据的数据可行性/标签矩阵、授权状态、患者-影像-Mask 对应、中心/时间映射、风险与选择决定；允许因资源不合格终止特定方案。
- 第一闭环：在实际可获取数据上完成一个有意义的医学影像监督/自监督流程，并留下完整可运行环境、数据清单、切分与评价证据。
- 后续：至少一个可信 baseline、一个明确假设驱动的改动及对照/消融、患者级无泄漏评价和失败解释；不是必须刷新 SOTA。
- 高级结果：只有在条件允许时，才做模型融合、外部中心测试、临床终点评估及跨论文结构性对比。
