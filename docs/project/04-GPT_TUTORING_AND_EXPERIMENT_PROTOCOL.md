# 04｜GPT 导师制逐步实操合同

## 用户自主管理与学习方式

MRI 数据处理、分割、Radiomics、训练和解释性等科研核心代码由用户逐步理解、编写、运行和审阅。GPT 应解释关键数据结构、算法原理、公式、输入输出、训练/预测边界与错误诊断，然后提供**当前最小有效代码段**；不一次性生成数千行看似可运行但无法消化的工程。Codex 不代写或运行上述核心代码。用户可在具体任务 Plan 中授权有界辅助自动化；本次 `CMRL-00` 明确授权仓库初始化、公开数据源与元数据核验、非敏感文件清点及证据报告。这项例外不授权发送访问申请、代填身份、接受未知条款、绕过访问限制、下载受限或超预算数据，也不改变核心代码教学边界；以后扩大须另行授权。

建议回合节奏：
1. 明确本回合实验子任务及其真实输入、成功判据。
2. 必需的理论/医学背景（中文＋英文术语），给有具体尺寸、病例数/中心约束的例子；复杂公式完整数值解释。
3. 给一段可理解、可独立测试的 Python 代码，逐段说明每一步和可能报错。
4. 说明运行命令、预期输出形态、如何查错；区分示例与实测，不伪称已在用户电脑运行。
5. 用户提供真实 stdout/stderr/截图/指标后复盘问题，接着推进。

必要时缩小步幅，如先阅读 1 张图的 shape 与 spacing，再批处理 678 名患者；先对一个体积提取一阶特征，再做大规模筛选。

## 实验开发的不可变安全守则

- 影像和掩膜必须先匹配患者、采集时点、检查序列及空间坐标；不同医院系统中的相同匿名编号并不保证同一患者。
- 按患者分组；切片、时点、增强副本均不得跨 train/val/test；外部中心须独立且无患者重叠。
- 标准化、特征选择、过采样、特征筛选、参数搜索等都在训练折拟合，验证/测试仅转换和评价。
- 预训练权重与模型许可、数据许可证分别审核。只处理获授权数据；不上传敏感 DICOM、实名病案、可重识别 ID 或完整医疗附件到聊天/公开 Git。
- 数据治理保留匿名化索引与来源；大影像 `data/raw` 不纳入 Git；仅可许可分享的摘要、配置、脚本和匿名聚合结果可公开。
- 所有指标标注 Data version / Patient count / Task / Positive class / Split / Confidence interval / Threshold / External-site。若任务为分割，不展示 AUC 作为默认主指标；若为应答，不展示 Dice 作为疗效指标。
- 环境使用由实际硬件决定的稳定配置，旧论文的 CUDA9/Python3.6 不是必须复用的标准。避免无意义精确数值复现承诺。

## 学习验证与知识记录

知识理解与运行证据分别看待：能解释 `tensor.shape` 与实际 batch 成功读取不是同一件事；训练能跑不代表标签正确；模型指标好不代表无泄漏。保留必要的问答与排查，但不过度考试。成熟技术内容可生成独立笔记，出题则附参考答案；实测结果必须附日志/命令/配置/文件校验信息。

## 运行失败如何诊断

按类别分流：数据找不到→患者索引/权限；掩膜错位→坐标系/重采样/方向；模型 shape 错误→channel-depth-height-width；CUDA OOM→分辨率/batch/patch；指标虚高→切片泄漏、目标泄漏或少数类；分中心效果差→域偏移与协议不同。优先最小可重复错误，不直接重写整个工程。

## 与旧课程保持隔离

原项目的 S0–S4/两轮精读继续独立存在。新项目的实验阶段 R0–R8 是**另一套进度和权限**；不要混写唯一课程 Checkpoint。原六篇是 Methods/Results 的事实参考，目标不是机械照抄其数字。用户可随时暂停实验、回到论文精读，再依据各自状态恢复。
