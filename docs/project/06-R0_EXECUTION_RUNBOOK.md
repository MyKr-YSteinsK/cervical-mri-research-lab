# 06｜R0 第一阶段执行手册（尚未执行）

当前目标不是立刻训练 3D 网络，而是回答：**有什么合法可得的数据？它究竟允许我们科学地做什么？**

## 一、三条并行核验路线

**D01：FlexFair/四中心 678 人**

1. 打开 Nature Communications 原文和 GitHub README，检查论文版本与 Figshare 两个不同记录号：`28639598` vs `28636133`。只从确认的真实官方链接下载。
2. 核实 Figshare 完整文件列表、下载方式与许可证。优先检查压缩内容结构与小体积样本，无须先下载安装全部数据。
3. 拿到数据后清点图像数量、Mask 数量、像素维度、样本命名、是否存在患者 ID、中心 ID、原始体数据与 spacing；确保 678 患者与几千张图片的关系被解释。
4. 如无法从文件中恢复患者级关联，不开展患者级 CV、Patient Dice 外推、三维体积 Radiomics 或 Leave-One-Center-Out 泛化主张；可做明确标为切片级的任务。

**D02：CCMD 151 人**

1. 核对官方 GitHub README 与期刊论文，并请用户决定是否具备可供申请的研究机构身份。
2. 用户亲自提出访问申请；申请前不要把“公开仓库”误认为“无需授权可下载”。仅保存联络状态，不在聊天中共享私人邮箱内容或密码。
3. 获得授权后检验 NRRD/DICOM/PNG 格式差异、Mask 与患者一一对应、物理空间、可否构建 3D 数据集；核对有无临床标签，未核实前按无标签处理。

**D03：TCIA 23 人**

1. 先下载官方小型 Clinical XLSX（13.9 KB），只查看去标识化字段名、取值、缺失值、时间定义。不要误把任何随访字段当 pCR。
2. 利用 TCIA/IDC 精确选择一名患者的一组影像、对应 RTSTRUCT，检查可下载性；不必一开始下载全 28.39 GB。
3. 识别序列、检查时间点/空间方向，提取真实肿瘤 ROI；若 RTSTRUCT 只含其他临床靶区或器官，写明其限制。

## 二、数据字典和文件检查的最小格式

| 字段 | 审核含义 |
|---|---|
| `source_dataset`、`license`、`source_version` | 真实数据来源与合法可用范围 |
| `patient_id`（匿名化）、`site_id` | 同人隔离和中心泛化的依据，缺失不可假填 |
| `study_date_or_relative_time`、`sequence` | 治疗前/中/后，T2WI/DWI/CE-T1WI 等 |
| `image_path`、`mask_path`、`mask_meaning` | 配对位置及 ROI 是否真正为肿瘤 |
| `shape_xyz`、`spacing_mm`、`origin`、`direction` | 是否可以安全重采样和计算三维空间特征 |
| `label_name`、`label_rule`、`label_time`、`reference_standard` | 仅真实存在时填写疗效/生存标签 |
| `data_quality_flag`、`missing_reason` | 缺失与异常保留，不用插补掩饰 |
| `split`、`center_holdout` | 训练/验证/测试互斥，按病人/中心划分 |

推荐先对一名病人的 1 对 MRI+Mask 做 `dtype`、`shape`、`spacing`、像素值、掩膜唯一值和 3 个正交切面的叠加可视化。基础检查通过后才写批量脚本。

## 三、GO / CONDITIONAL / NO-GO

- `GO-SEGMENTATION`：Image/Mask 真实配对、标签定义清楚、有明确患者（若没有，只能限定为 2D 图片级评估）、许可可用、划分方案合理。
- `GO-RADIOMICS`：在 GO-SEGMENTATION 之外，有可信的空间信息与 ROI 定义及稳定的预处理策略。
- `GO-HABITAT`：有能支持亚区域的连续空间影像或对齐序列，并设计合理的无监督/监督验证；小样本仅探索性。
- `GO-RESPONSE`：另有**真实**治疗应答标签、治疗与影像时点的合理对应、足够病例与类比例，且切分没有跨患者泄漏。
- `CONDITIONAL`：数据格式、授权、对应或患者标识待解决；仅进行不会制造伪证据的演示。
- `NO-GO`：无许可、无法辨认 ROI、无对应图像/标签或存在不可排除的数据泄漏风险。

## 四、R0 完成应该报告什么

1. 已检查的官方数据源与发布版本、资源实际可下载状态（报告 HTTP/链接/文件量，不复制敏感 token）。
2. 文件清单、患者/图片数、可用模态与 ROI 类型；矛盾清单和证据截图/摘要。
3. 用户设备与磁盘是否支持第一实验；不强制 GPU 即开工。
4. 最合适的 **1 个当前可交付主任务**，可以从分割开始；清楚说明后续扩展需要哪种新增数据。
5. 三种决策之一：按可核对数据进入 R1；等待合法访问并暂做 TCIA 小样本处理；或重新搜索数据。

## 五、首轮与用户沟通

不做长表格需求调查。只在真正需要决定运行环境时询问：系统（Windows/WSL/Linux）、GPU 型号和显存、可用空闲磁盘；CCMD 申请需要时再询问是否具备研究机构身份。不要让用户一次性提供真实患者影像。代码建议以 CPU 上少量数据探索为第一步。
